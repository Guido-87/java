# Documentation Standards

- Write project guidance and technical documentation in English. Keep user-facing text in the language appropriate to the application.
- Update documentation when a change alters setup, configuration, API behavior, data storage, or project conventions.
- Treat source code and configuration as authoritative. Do not document placeholder entities, endpoints, or architecture as implemented facts.
- Keep `api-spec.yml` aligned with the actual HTTP contract and `data-model.md` aligned with actual persistence behavior.
- Keep OpenSpec artifacts consistent with implementation and the current `openspec/config.yaml`.
